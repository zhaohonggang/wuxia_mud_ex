## 2. 收徒门（apprentice）：无条件暂不收徒

`tangmen.h permit_recruit()` 的第一条语句是**无条件**回绝：

```c
command("say 对不起，唐门暂不收徒，你过段时间再来吧。");
return 0;
```

其后 detach/betrayer/born_family/他派各分支，以及 `tangrou.c attempt_apprentice()` 中
「你已是我唐门人…找我大师兄吧」分支，**在 LPC 中均不可达**；照搬会改变行为，
故不落为门控，仅在此留档。`attempt_apprentice` 中被注释掉的 str/dex/int 门槛同理（非生效逻辑）。

ex 落法（与 miao/星宿/玄冥等 `deny_all` 先例一致，由 `npc_shop_event.ex:157` 消费，
逐字回显、不加敬称）：

```
apprentice = {
  deny_all = true
  deny_msg = "对不起，唐门暂不收徒，你过段时间再来吧。"
}
```

## 3. 战斗属性 / 装备 / 战斗闲聊

- `apply`（combat 块内）：`damage = 100`、`unarmed_damage = 100`、`armor = 200`；
  LPC 未设 attack，保持默认 0。
- `chat_chance_combat = 20`；`chat_msg_combat = ["recover", "powerup", "throwing.san"]`
  （转换器降级的原始字符串，与 emei/meizhuang 等既有约定一致）。
- `carry`：cloth（clone_lib）+ 毒蒺藜（`/d/tangmen/obj/jili` → `tangmen.items.jili.id`）
  + 飞刀（`/d/tangmen/obj/feidao` → `tangmen.items.feidao.id`）。
  注意 clone_lib 自身另有一个**铁蒺藜** `items "jili"`，不是 LPC 这里的毒蒺藜，不能用。

## 4. 已登记缺口（不简化、不静默丢弃）

- **GAP #898**：NPC 的 `set("shen", 2000)` / `set("max_jingli", 1000)` / `set("jiali", 100)` /
  `set("level", 8)` 在 ex 的 `npc_stats/1`、`parse_vitals/1` 中均无对应字段（loader 恒写
  `shen: 0`，vitals 无 jingli）。属通用 NPC 属性建模缺口，非唐门独有，需统一评估。

  出生时的初始 temp/prepared 状态；loader 无对应 UCL 字段（玩家侧 `prepare_command`/`hand_command`
  已有）。本批以 carry 放入 jili 覆盖「持有」部分，初始 handing 槽位与 prepared 映射待补。
- **GAP #900**：`set("master_ob", 2)` 在 LPC 仓库内除本文件外无消费端（`adm/single/master.c` 的
  同名符号是无关的 wizard 命令），含义待考；不伪造 ex 语义。
