### 1.3 `attempt_apprentice`（拜师应答）—— **本批核心缺口**
```c
int attempt_apprentice(object ob)
{
    if (!ob->query("born")) {
        command("say 你快投胎去，在这里瞎搅和什么？");
        return 0;
    }
    command("say 滚！给我一边儿去！");
}
```
- **无 `born`** → `say 你快投胎去，在这里瞎搅和什么？`（拒绝）
- **有 `born`** → `say 滚！给我一边儿去！`（拒绝）
- 两个分支**都拒收**，但**文案按 `born` 分条件**。

**ex 实现后现状**：`register.ucl dizangwang` 补 `apprentice.deny_all = true` +
`deny_msg_by_born`：无 born → 「你快投胎去，在这里瞎搅和什么？」；有 born/`*` →
「滚！给我一边儿去！」。`NpcFamilyEvent.deny_reason/3` 从 `room.ex` 传入的
`student_born_family` 选文案，两分支均拒绝，不再落通用「并无门派」文案。

## 2. 实现（随 #1044 落地）

### 2.1 引擎机制
`apprentice.deny_all` 原有单一静态 `deny_msg` 无法表达按 `born` 分条件的双文本。
#1044 统一扩展 `loader.parse_apprentice/1` 与 `NpcFamilyEvent.deny_reason/3`，
新增 `deny_msg_by_family` / `deny_msg_by_born`；`room.ex` 在 `family/apprentice`
事件里附带 `student_family` / `student_born_family`。中文条件值不能作 UCL map key，
故写为数组对象 `{ born = "..." msg = "..." }`。

### 2.2 数据落地
`register.ucl` `characters "dizangwang"`：
```ucl
apprentice = {
  deny_all = true
  deny_msg = "地藏王说道：滚！给我一边儿去！"
  deny_msg_by_born = [
    { born = "(none)" msg = "地藏王说道：你快投胎去，在这里瞎搅和什么？" },
    { born = "*" msg = "地藏王说道：滚！给我一边儿去！" }
  ]
}
```
无 born → `(none)` 分支；有 born → 命中具体值或 `*` 通配；两分支均拒绝。
