## 0. 结论先行

`kungfu/class/hell/` 下**只有 `dizangwang.c` 一个文件**，即地藏王——本「门派」实为冥府地藏王殿前家族的**唯一师父**，且 `attempt_apprentice` **只拒不收**（投胎引导）。hell 无独立武功套（地府阴/鬼功夫归各技能文件，由其它区/派传授）。

该 NPC 已在 ex `register.ucl` 转换，**缺的仅是 `attempt_apprentice` 的 `born` 双分支拒绝文案**——这暴露的是**引擎级「条件分文案」机制缺口**（`deny_all` 只支持单一静态 `deny_msg`），与 GAP #1044（无名同门/异门分条件）同类，**并入 #1044 一并实现**。

### 1.2 `greeting`（init → greeting，进 startroom 触发）
LPC 双分支（hell 用 `wash`，register 用 `washto` + 天书）：
- **无 `born`**：
  - hell：`say <name>，你快快在无忧池中洗脱筋骨(wash)，然后投胎去吧！`
  - register：`say <name>，你快快在无忧池中洗脱筋骨(指令：washto)，然后投胎去吧！`
  - register 额外：若 `present("heros book")` 不存在 → `tell_object` 悄声给一本天书（newbie_book）+ `grin` + `ke`。
- **有 `born`**：
  - wizard → `heihei <id>`
  - 非 wizard → `kick <id>` + `say 凡人跑到这里来干什么？` + `message_vision "$N一脚把$n踢得无影无踪。"` + `move(VOID_OB)` + `message_vision "$N跌落地上，捂着屁股哇哇叫了几声。"`

ex `register.ucl` 现有：`greetings` 仅含 kick 两条视觉文案（`{npc}一脚把{name}踢得无影无踪。` / `{npc}跌落地上，捂着屁股哇哇叫了几声。`）。**born 分支的投胎引导 / 天书 / 踢飞逻辑是否由 login/setup_controller 或其它 handler 承接，需实测确认**——本计划聚焦教学门控，greeting 流程不在本批实现范围（若发现缺失另立 GAP）。

### 1.3 `attempt_apprentice`（拜师应答）—— **本批核心缺口**
```c
int attempt_apprentice(object ob)
{
    if (!ob->query("born")) {
        command("say 你快投胎去，在这里瞎搅和什么？");
        return 0;
    }
    command("say 滚！给我一边儿去！");
}
```
- **无 `born`** → `say 你快投胎去，在这里瞎搅和什么？`（拒绝）
- **有 `born`** → `say 滚！给我一边儿去！`（拒绝）
- 两个分支**都拒收**，但**文案按 `born` 分条件**。

**ex 现状**：`register.ucl dizangwang` **无 `apprentice` 块、无 `teach.family`** → `NpcFamilyEvent.apprentice/2` 走 `apprentice_reply` 的 `teach.family == nil` 分支，回**通用文案**「摆了摆手：老朽并无门派，不敢误人子弟。」——**与 LPC 地藏王双文本不符**。

## 2. 缺口与实现方式

### 2.1 引擎机制缺口（GAP #1044 扩展）
`apprentice.deny_all` 仅支持**单一静态 `deny_msg`**，无法表达按 `born` 分条件的双文本。同类问题：#1044 无名按门派分支、地藏王按 born 分支。

**建议扩展**（待 #1044 一并设计，不在此实现）：
- 方案 A：`apprentice` 增加条件分文案键，如
  ```
  apprentice {
    deny_all = true
    deny_msg = "滚！给我一边儿去！"
    deny_msg_born_unset = "你快投胎去，在这里瞎搅和什么？"
  }
  ```
  引擎在 `NpcFamilyEvent.apprentice/2` 按 `character` 的 `born` flag 选择文案。
- 方案 B：统一引入条件化 deny 块（复用 #1044 的设计），地藏王登记 `born` 条件键。

### 2.2 数据落地（实现 #1044 引擎后）
`register.ucl` `characters "dizangwang"` 补 `apprentice` 块，表达 born 双分支拒绝（两条逐字文案），保证 `baishi dizang` 输出 LPC 原文而非通用「并无门派」。
