## 2. 缺口一：`recognize_apprentice` 按技能授课门控

### LPC 原文（`kungfu/class/hu/cheng.c:49`）

```c
int recognize_apprentice(object me, string skill)
{
    if (me->query("family/family_name") != "关外胡家") { say("你是谁？来干什么？"); return -1; }
    if (skill != "poison" && skill != "dispel-poison" &&
        skill != "medical" && skill != "yaowang-miaoshu")
        { say("我只会毒功和医术，别的我就没法子教你啦！"); return -1; }
    if ((int)me->query("shen") < 0) { sigh(); say("你怎能走上邪路？我可不能教你。"); return -1; }
    if (!me->query_temp("can_learn/cheng/poison")) {
        me->set_temp("can_learn/cheng/poison", 1);
        say("看在胡斐的面子上，我就教你一点本事吧，你可要好自为之！");
    }
    return 1;
}
```

### Elixir 侧现状

- `loader.parse_teach/1` 只解析 `family` / `teach_skills` / `no_teach` 三项。
- `teach` 块当前仅供门派信息展示；`skills_event.teach/2` 只走
  `SectMaster.teachable?/3`（同门派 + 师父等级高于学生）。
- 已有 `Family.recognize_apprentice/3` 是**入门确认**，语义不同，不能复用。

### 移植方案

1. **UCL schema**：`teach` 块新增
   - `recognize_family = "关外胡家"`
   - `recognize_skills = ["poison", "dispel-poison", "medical", "yaowang-miaoshu"]`
   - `min_shen = 0`（授课侠义下限）
   - `recognize_deny` / `skill_deny` / `shen_deny` 三条 LPC 原文
   - `first_learn_msg` 首次授课台词 + `first_learn_mark = "can_learn/cheng/poison"`
2. **loader**：`parse_teach/1` 透传上述字段（保持缺省 nil，老数据零影响）。
3. **消费端**：`skills_event.teach/2` 在 `SectMaster.teachable?/3` 之前插入
   `SectMaster.recognize_gate?/3`；失败直接回执对应 LPC 文案。
4. **标记**：首次命中时写 `student_marks[first_learn_mark]`（沿用
   `Kantele.Combat.Skill.mark?/2` 的 `meta.marks` 通路），并回显
   `first_learn_msg`。LPC 用 `set_temp`，此处按猎人模块先例同时写 temp 与 marks。
5. **测试**：`sect_master_test` 覆盖四条拒绝分支 + 首次/再次授课文案；
   loader 测试确认字段落位；定向 + 全量回归。

## 3. 缺口二：`no_teach` 闭包解锁（`can_learn/hufei/*`）

### LPC 原文（`kungfu/class/hu/hufei.c:97,210-259`）

`no_teach` 不是字符串列表，而是 `skill -> closure` 映射：

| 技能 | 解锁门槛（`combat_exp >`） | 成功台词 | 未达标台词 |
| --- | --- | --- | --- |
| baisheng-daofa | 100000 | 不错，不错！今日我便传授你百胜刀法。 | 你此时功力太浅，我还是先传授你一些简单的刀法。 |
| hujia-daofa | 400000 | 既然你能有如此造诣，我今日便传授你胡家刀法！ | 你的实战经验不足，尚难以领会这高深胡家刀法。 |
| sixiang-bufa | 50000 | 看来你武功已经有了一定的基础，今日我就传你四象步法。 | 四象步法对你来说过于艰深，你还是先奠定好基础再说。 |

解锁后写 `can_learn/hufei/<skill> = 1`，已解锁再问则静默放行（return 0）。

### Elixir 侧现状

- `loader.parse_teach/1` 的 `no_teach` 只接受 list，map 会被静默丢弃为 `[]`。
- `no_teach` 全库无消费端（仅展示）。
- `meta.marks` 已有 `can_learn/...` 通路（`Kantele.Combat.Skill.mark?/2`），可复用。

### 移植方案

1. **UCL schema**：`teach` 块新增 `unlock_skills = [ { skill = "..." min_exp = N
   mark = "can_learn/hufei/..." unlock_msg = "..." deny_msg = "..." } ]`；
   与既有平坦 `no_teach` 列表并存，互不影响。
2. **loader**：`parse_teach/1` 解析该列表为结构化 map（键为 skill id）；
   老数据无此键时为 `%{}`。
3. **消费端**：`skills_event.teach/2` 查到待学技能在 `unlock_skills` 中时，
   先判 mark → 再判 `student_stats.combat_exp > min_exp`：
   - 达标：写 mark + 回显 `unlock_msg`，然后继续正常授艺流程；
   - 未达标：回显 `deny_msg` 并终止。
4. **测试**：三档边界（等于阈值不解锁 / 大于解锁）、已解锁静默、文案逐条；
   loader 落位测试；定向 + 全量回归。

## 4. 非缺口项（已按 LPC 原样保留）

- 胡斐 `ask_baodao` / `ask_jundao` / `ask_quanjing` / `ask_daopu` 为**给物品**问询，
  当前 `give_item` handler 无胡家物品条目，按既往约定保留
  `inquire about ... (unimplemented)` 占位，不伪造实现。
- 胡逸之 `ask_me`「百胜刀法」仅按门派回文本，无授予行为，已保留为文本问询。
- 胡斐 `permit_recruit` 的 `born_family == 关外胡家` 与
  「胡一刀/胡斐/胡子/胡臭」拒名分支当前 `apprentice` schema 无字段承载，
  已在 UCL 块内以注释逐条保留原文；如需真实生效，另立任务扩展 apprentice schema。
