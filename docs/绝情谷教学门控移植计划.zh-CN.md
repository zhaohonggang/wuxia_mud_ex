## 1. 缺口结论

UCL 中 `jueqing_chi` / `jueqing_fan` / `jueqing_zhi` 三个角色块**只有 skills/combat/carry**，
完全没有 `teach`、`apprentice`、`inquiries`。而 LPC 三份源码均含：

| NPC | LPC `set_skill` | `attempt_apprentice` | `accept_ask` 绝招 | `give_item` | QUEST_D |
| --- | --- | --- | --- | --- | --- |
| 裘千尺 `chi.c` | 22 项（strike 重复一次） | 5 道门 + 改姓 | 5 | 0 | 3 键 |
| 樊一翁 `fan.c` | 20 项 | 1 道门 | 8 | 0 | 0 |
| 公孙止 `zhi.c` | 23 项 | 5 道门 | 9 | 2 | 3 键 |

合计 **22 条绝招问询 + 2 条物品授予 + 3 组历练键**，共需回填 3 个 `teach`、
3 个 `apprentice`、3 个 `inquiries`。

## 2. 数据回填映射（Task #745）

### 2.1 `teach`（wrapper 格式，loader 只认 character 级 `:teach`）

- `family = "绝情谷"`（三名 NPC 一致，LPC `create_family("绝情谷", ...)`）。
- `teach_skills` 取 LPC `set_skill` 全部**唯一**条目；重复 `strike 260`（chi.c:42/43）
  只保留一份。值格式 `max = <LPC 等级>`、`gongxian = 0`（与既往批次一致）。
- 不写 `no_teach`：三份 LPC 均无拒教表。

### 2.2 `apprentice`（顺序严格对应 LPC `attempt_apprentice`）

| 顺序 | 裘千尺 | 樊一翁 | 公孙止 |
| --- | --- | --- | --- |
| 1 | `permit_recruit` | `permit_recruit` | `permit_recruit` |
| 2 | `reject_master_name = "公孙止"` + 原文拒绝 | — | `reject_master_name = "裘千尺"` + 原文拒绝 |
| 3 | `max_shen = -60000`（`shen > -60000` 拒） | `max_shen = 0`（`shen > 0` 拒，两句文案） | `max_shen = -30000`（两句文案） |
| 4 | `min_exp = 400000` | — | `min_exp = 300000` |
| 5 | `min_skills = { force = 140, strike = 80 }` 逐技能文案 | — | `min_skills = { jueqing_xinfa = 120, dodge = 180 }` 逐技能文案 |
| 成功后 | 两句收徒文案 + 公孙姓改裘姓 + 两句改名文案 | 一句收徒文案 | 两句收徒文案 |

阈值注意：LPC 负神门槛是**上界**（`shen > 负数` 即拒），必须落到 UCL `max_shen`，
不能误写 `min_shen`（语义相反）。三名 NPC 均无侠义下限，须显式写
`no_min_shen = true` 关闭引擎缺省的 `min_shen = 0`，否则负神玩家会被误拒。

改名：LPC `chi.c:132-145` 仅当 `surname == "公孙"` 时把姓改为「裘」并改名；ex 用
`rename_surname_from = "公孙"` / `rename_surname_to = "裘"` / `rename_surname_index = 2`
（按 grapheme 跳过的姓长度）+ 两句文案，复用 `NameD` + `Characters.rename_by_name` 管线。

### 2.3 `inquiries`（`sect_master_grant` / `give_item`）

- LPC `teach_pfm` 的 `shen` 为负 → UCL `max_shen`（配 `max_shen_deny` = masterd 原文
  「哼！像你这样的心慈手软之辈，又能干成什么大事？」）。
- `gongxian` → `min_gongxian` + `cost_gongxian`；LPC 扣贡献原文见 masterd.c:337+。
- `sk1/lv1` → `min_levels = { <skill> = lv1 }`；另有 `force` / `dodge` 也并入 `min_levels`。
- `msg1` → UCL 字段 `msg_one`（UCL 标识符不能含数字，`msg1` 会触发
  `syntax error before: "1"`），由 `SectMasterGrant` 用 `Helpers.broadcast/3` 作房间广播
  （LPC `message_sort(...)`）；`learned` 保持「你学会了「X」。」玩家私聊。
- `perform` 字符串 `"can_perform/<skill>/<id>"` → `perform_id = "<skill>/<id>"`。
- 裘千尺「掌心雷」`shen = -950000` **按 LPC 原值保留**，不因看似笔误而「修正」。
- 逐字保留 masterd 拒绝文案（门派/贡献/技能/内功/轻功），`level_deny` 用技能 id 映射。
- 公孙止两件物品：`item = "clone_lib:heijian"` / `"clone_lib:juchidao"`；
  `master_id = true`（LPC `"master" : 1`，仅嫡传弟子）；`max_shen = -46000/-50000`；
  `min_skill_levels = { yinyang_ren = 150/180 }`；`unique = false`（LPC give_item 无 present 检查）。
- `QUEST_D` 三键按既有批次写 `unimplemented` 标记，不得伪造实现（见缺口 #747）。

## 3. 引擎扩展（本批内实现，零回退）

1. `Kantele.SectMaster.recruit_gate?/3` 新增 `reject_master_name` 门控，读
   `meta.family.master_name`；`loader.parse_apprentice/1` 透传 `reject_master_name` /
   `reject_master_name_deny`。位置：permit_recruit 之后、max_shen 之前（对齐 LPC）。
2. `Kantele.World.InquiryHandlers.SectMasterGrant` 支持 `msg1` 房间广播；
   `data.npc_room_id` 缺失时不广播、不影响既有 grants（UCL 目前无 `msg1`）。
3. `Kantele.Character.FamilyEvent.maybe_rename/3` 增加按姓改名分支
   （`rename_surname_from/to/index` + `rename_surname_msg`），复用现有 NAME_D 流程。
   `accept_msg` 允许 UCL 覆写收徒成功文案，未配置时保持原默认文案。
4. `Kantele.SectMaster.inquiry_grant/3` 增加 `gate_order = "lpc_masterd"` 可选顺序：
   同门 → 已会 → 神 → 贡献 → 技能存在 → 技能等级 → 内功/轻功。缺省顺序不变，
   老配置零影响；绝情谷 22 条 grant 全部显式启用，保证门控冲突时拒绝文案与 LPC 一致。
   `level_deny` 现在支持逐技能 map（按 sk1 → force → dodge 顺序取第一个未达标项）。
5. `apprentice.no_min_shen = true` 关闭引擎缺省 `min_shen = 0` 下界；
   `min_exp_deny` 逐字覆写经验不足文案。二者均为显式 opt-in，老配置零回归。
