## 2. 本批实现（Task #804）

### 2.1 teach 数据（9 NPC）

LPC 各 NPC 的 `set_skill` 逐条落为 `teach = { family = "逍遥派" teach_skills = {...} }`，
`max` 等于该 NPC 自身技能等级。苏星河的 `no_teach` 是 map（硬拒）而非列表：

```ucl
no_teach = {
  zhemei_shou = "逍遥折梅手乃本门神功，只能由掌门人传授。"
  liuyang_zhang = "这天山六阳掌向来只能由逍遥派掌门传功，我不便教授。"
}
```

两项同时从 `teach_skills` 中剔除，避免与 `no_teach` 冲突（慕容博同款做法）。

统一使用 `gate_order = "lpc_kunlun"`：LPC 顺序为「已会 → 同门 → 必修技能≥1 →
贡献 → 逐条 level_order」，与 kunlun handler 一致；`level_order` 先 `force` 后本门技能，
保证「内功不足」与「招式火候不足」不会互换文案。化妖功 `level_order` 为
`["zhemei-shou", "max-neili"]`（`max_neili` 是 kunlun handler 已支持的伪技能键）。
`improve_skills` 保留化妖功 LPC 中三连 `improve_skill("hand")`、三连
`improve_skill("force")` 的原始重复次数（不合并）。

### 2.3 apprentice 门控引擎扩展

`xiaoyao.h permit_recruit` 的第四条是 `query("per") < 28`，现有引擎无容貌门，故新增：

- loader `parse_apprentice/1`：`min_per`、`per_deny`、`any_min_skills`、
  `any_min_skills_deny`。
- `SectMaster.recruit_gate?/3`：
  - `min_per` 置于 `permit_recruit` 三条之后（对应 `xiaoyao.h` 内部顺序）；
  - `any_min_skills` 为 OR 门（无崖子「逍遥心法/小无相功/北冥神功任一≥130」）；
  - `gate_order = "lpc_xiaoyao"`：悟性硬门先于经验门（苏星河 int30 → exp200000 → force/心法）；
  - `gate_order = "lpc_wuyazi"`：技能 OR → force/dodge → int → exp（无崖子常规分支顺序）。

全部字段缺省时不改变任何既有 NPC 行为。
