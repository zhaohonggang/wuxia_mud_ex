## 1. 审计结论

商家堡在早期 #619 批次落齐了 3 位师父的 `skills` / `teach` / 绝招 `inquiries`，但**收徒门控全错、
守卫与战斗行为大面积缺失**，另有一处**NPC 重复定义**：

1. **收徒门控：`shang.h::permit_recruit` 无条件 `return 0`（3/3 全拒）**

   ```c
   int permit_recruit(object ob)
   {
           command("say 我商家堡武功脱胎于八卦门，不对外收徒。");
           return 0;
   }
   ```

   商剑鸣 / 商老太的 `attempt_apprentice` 都以 `if (! permit_recruit(ob)) return;` 开头，
   其后所有判定（改名冲突 / `combat_exp` / `shen` / 内功 / `family/master_name`）**全部不可达**；
   商宝震**不**调 `permit_recruit`，自己 `command("shake")` + `command("say ...")` 回绝。
   UCL 现状：`shang_ming` / `shang_tai` 的 `apprentice` 块抄了不可达的
   `max_shen = -30000` / `min_exp = 300000` / `min_skills{shangjia_neigong = 100}`；
   `shang_zhen` **没有 apprentice 块**（拒徒台词整段缺失）。
   → 3/3 改为 `deny_all = true` + 逐字 `deny_msg`；不可达门以注释保留（与凌霄城 #24 同口径）。

2. **商剑鸣被复制成两份（本批最严重）**

   - `clone_lib.ucl characters "shang_ming"`：**全量**（`teach` 24 技能 / `apprentice` /
     `inquiries` 11 键 / `skills` 24+9 / `carry`）。
   - `shaolin.ucl characters "shang_jianming"`：**薄定义**（只有 name/aliases/description/
     nickname/title/gender/class/attitude/age/`shen_type`/`combat`+`skills`+`map_skill`，
     外加一段**写法错误**的 `inquiries = [{ key = "胡一刀" value = "..." }]` —— loader 的
     `inquiries` 是 map，不是 list-of-maps，这段等于没生效）。
   - `shaolin.ucl room_characters "shang_dating"` **同时列了两者**
     （`{ id = characters.shang_jianming.id }` + `{ id = characters.shang_ming.id }`）
     → **大厅里有 2 个商剑鸣**；LPC `shang_dating.c set("objects", ([".../ming" : 1]))` 只有 1 个。
   - → 从 `room_characters "shang_dating"` 删掉 `shang_jianming`；退役 `shaolin.ucl
     characters "shang_jianming"` 整块（唯一引用点就是 shaolin.ucl:3002）。

3. **商宝震 F_GUARDER + coagents 全缺**

   `zhen.c` 同时 `inherit F_GUARDER`，并：

   ```c
   set("coagents", ({ [ "startroom" : "/d/shaolin/shang_dating", "id" : "shang jianming" ] }));
   set("guarder", ([
       "refuse_other": CYN "$N" CYN "对$n" CYN "冷喝道：你给我站住！我们商家堡岂是由得外人随便走动地方？" NOR,
       "refuse_carry": CYN "$N" CYN "对$n" CYN "喝道：你背上背的是什么人？给我放下来！" NOR,
   ]));
   ```

   UCL `shang_zhen` 无 `meta.guarder`、无 `coagents`。
   → 补 `meta.guarder { family = "商家堡" msgs = { refuse_other / refuse_carry } }`
   + `coagents = [{ id = "shang jianming" startroom = "shaolin:shang_dating" }]`
   （参照 `clone_lib.ucl` 陆万通 29112–29128 的同形块）。

4. **`d/shaolin/shang_men.c::valid_leave` 只守 north**

   ```c
   if (dir != "north"
      || ! objectp(zhen = present("shang baozhen", this_object()))
      || (me->query("born_family") == "山东商家" && ! me->query("family/family_name")))
           return ::valid_leave(me, dir);
   return zhen->permit_pass(me, dir);
   ```

   - 只 `north` 一向（`south` 直通官道）；
   - 商宝震不在场则放行；
   - **`山东商家` 出身且未入门派者放行**（不走守卫判定）。
   - UCL `rooms "shang_men"` 无 `behavior` / `behavior_config` → `room.ex guard_direction/2`
     落到 `true -> :skip`（fail-open），守卫恒不拦。
   - → 补 `behavior = "guarded_exit"` + `behavior_config = { guard_directions = ["north"] }`
     （模板见 `data/world/lingxiao.ucl` 大店 245–273）。
   - `山东商家` 出身旁路 `Kantele.Npc.Guarder.permit_pass/1` 无法表达 → **GAP #1036**。

5. **`d/shaolin/shang_dating.c::valid_leave` 的家族门本已落在 exit_vetoes**

   ```c
   if (dir == "north" || dir == "east" || dir == "west") {
       if ((string)me->query("family/family_name") != "商家堡" &&
           (string)me->query("born_family") != "山东商家" &&
           objectp(present("shang jianming", environment(me))))
           return notify_fail(CYN "商剑鸣对你喝道：什么东西，居然敢在我面前放肆！\n" NOR);
   }
   ```

   UCL `rooms "shang_dating"` 已有
   `valid_leave = [{ condition = "... && (dir == 'east' || dir == 'north' || dir == 'west')",
   direction = ~, message = "商剑鸣对你喝道：什么东西，居然敢在我面前放肆！" }]`。
   - `direction = ~` → 解析为 `"*"`（全向），由条件里的 `dir ==` 子句限定三向；
   - `LpcCondition.direction_scoped?/1` 命中条件里的 `dir` → 可执行；
   - `config/config.exs:26` 设 `enforce_exit_vetoes = true` → **本已生效**（dev/test 均开）；
   - 条件里的 `present('shang jianming', environment(me))` 靠 `shang_ming` 的 aliases
     （含 `"shang jianming"`）命中（`ExitVetoContext.name_matches?/2` 查 name + aliases）
     → 删除薄副本后仍成立。
   - → **无需改动**，本批加测试锁定。

6. **商老太 `no_teach.wai-bagua` 被拍平成列表**

   LPC：

   ```c
   set("no_teach", ([
           "bagua-dao" : "八卦刀需由我夫君亲自传授。",
           "wai-bagua" : (: try_to_learn_waibagua :),
   ]));
   ```

   `cmds/skill/learn.c:79-91`：`no_teach/<skill>` 是**字符串** → 逐字拒；是**闭包** → 求值，
   返回字符串 → 拒，返回 `0` → **放行**。`try_to_learn_waibagua()`：

   - 已持 `can_learn/shanglaotai/wai-bagua` → `return 0`（放行）；
   - `combat_exp > 100000` → `say 看来你武功已有了一定火候，我就替夫君传你外八卦神功。`
     + `set mark` + `return 0`（放行）；
   - 否则 → `"你此时功力太浅，还是先学一些入门功夫吧。"`（拒）。

   ex `SectMaster.check_mark_exp_unlock/3` 形状一一对应：
   `has mark → {:unlock, learned, nil}`；`exp > min_exp → {:unlock, learned, mark}`；
   `else → {:error, locked}`（严格 `>`，与 LPC `combat_exp > 100000` 同界）。
   UCL 现状是 `no_teach = ["bagua-dao", "wai-bagua"]`（flat list → 只进展示，文案全丢）。
   → 改成 map 形态：

   ```
   no_teach = {
     bagua_dao = "八卦刀需由我夫君亲自传授。"
     wai_bagua = {
       unlock = {
         mark = "can_learn/shanglaotai/wai-bagua"
         min_exp = 100000
         learned = "看来你武功已有了一定火候，我就替夫君传你外八卦神功。"
         locked = "你此时功力太浅，还是先学一些入门功夫吧。"
       }
     }
   }
   ```
