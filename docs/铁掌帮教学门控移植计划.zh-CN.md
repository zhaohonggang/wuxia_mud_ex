## 5. 引擎复核与一处真实缺口修复

所需字段（`allow_families` / `defer_*` / `delete_mark_on_accept` / `recruit_skill_order` / `no_min_shen` /
`max_shen` / `lpc_masterd` / `level_order` / `msg_one`）均已在既有引擎中落地，未新增 gate_order。

实测发现一处共享引擎缺口：`inquiry_grant_lpc/3` 的有序链用 `named_level_value/2` 正确读取
`max_neili`，但**未配置 `level_order` 时的回退**仍走 `meets_levels?/2` 的纯技能查表，把
`max-neili` 伪键当成技能等级 0。铁掌帮穿心锥（LPC `neili=200`）因此恒被误拒。
修复方式为仅在该路径新增 `meets_named_levels?/2`（普通技能仍委托 `named_level_value/2 → skill_level_of/2`），
其它 gate_order 零影响。此改动已纳入待全量回归清单 #12。

### 7.1 本批修掉的两个静默陷阱

1. **UCL 数组语法**：`level_order = [ "a" "b" ]` 无逗号会被 Elias 拒绝；必须写成
   `[ "a", "b" ]`。嵌套 map 作为数组元素在**有房间的区文件**（如 tiezhang.ucl）里不能写
   `} },`，须拆成 `}` 换行 `},`，否则校验器的双右括号启发式会报错（clone_lib 是无房间库文件，
   该启发式跳过）。
2. **inquiry 配置不解析物品引用**：`item = items.zitie.id` 到 loader 后仍是字面字符串，
   而 `GiveItem` 需要 `"zone:key"`；必须直接写 `item = "tiezhang:zitie"`。已加断言锁定。
