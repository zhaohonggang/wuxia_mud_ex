## 2. 本批实现（Task #811）

### 2.1 teach 数据（7 NPC）

每个 NPC 的 `set_skill` 逐条落为 `teach = { family = "星宿派" teach_skills = {...} }`，
`max` 等于该 NPC 自身等级。四名 NPC 的 `no_teach` 是 map（硬拒）而非平坦列表，
对应技能同时从 `teach_skills` 中剔除：

- 阿紫：`huagong-dafa` → 「化功大法让老仙教你吧，我可不愿被他罚。」
- 狮吼子／天狼子／摘星子：`huagong-dafa` → 「化功大法要老仙亲自传授。」

丁春秋、出尘子、星宿弟子无 `no_teach`，化功大法照常列入教学技能。

`level_order` 显式固定 `masterd.c` 的 `sk1..sk5 → force → dodge → neili` 顺序；
`min_force` 对应 `b["force"]` 这道**独立于 sk1..sk5** 的内功门（夺魂势同时有
`sk2=force 130` 与 `force=80`，两条都保留，不合并）。`min_max_neili` 对应 `b["neili"]`。
`improve_skills` 按各招主技能 + `valid_enable` 命中的基本技能 + 武学修养落地，
逐项 +1 级，对应 LPC 的 `improve_skill(...,1500000)`。

### 2.4 apprentice 门控

- 摘星子：`shen > 0` 即拒 → `no_min_shen = true` + `max_shen = 0` + LPC 逐字文案。
- 丁春秋：`shen > -12000` 拒 → `no_min_shen = true` + `max_shen = -12000`；
  之后 `combat_exp ≥ 300000`、`chousui-zhang ≥ 120`、`poison ≥ 120`，
  三句拒绝文案逐条落在 `min_exp_deny` / `min_skills_deny`。
- 阿紫／出尘子／星宿弟子／狮吼子／天狼子：LPC `attempt_apprentice` 无条件拒收
  （星宿弟子源码甚至没有该函数），落为 `deny_all = true` + 对应原文。
- `xingxiu.h welcome()` 的叛门/判师/他派三句按既有批次惯例落为
  `permit_recruit` 三件套；其中他派文案含动态门派名，UCL 用静态近似并已注明。

## 3. 已报告缺口（不得简化，逐项建任务）

- **#812 丁春秋 flatter 两步拜师**：`ding.c:141-200` 在数字门通过后只设
  `pending/flatter` 并提示「我星宿老仙比起古往今来的圣人怎么样啊？」；
  玩家须执行 `flatter`，且话中同时含「星宿老仙」与「德配天地／威震寰宇／
  古今无比」之一才 `recruit`。ex 虽已有 `init.add_actions = ["flatter"]`，
  但无命令处理器与 pending 状态，当前一步收徒。需新增状态机 + 文案匹配。
- **#813 QUEST_D 历练问询**：`ding.c:300-307` 的「历练／历炼／锻炼」走
  `QUEST_D->accept_ask`；ex 无门派 quest 分发（与 #744/#747 同类）。当前保留
  明确 `unimplemented: GAP #813` 占位。
- **#814 香料多状态**：`ding.c:260-288` 有 `is_busy/is_fighting` 拒绝、
  每玩家 `get_xiangliao` 临时标记 + `call_out(...,180)` 冷却、
  `random(50)+100` 数量、`xiangliao_count = random(10)+10` 随机初值。
  现有 `GiveItem` 仅能表达 family/poison/count。
- **#815 coagents 助战**：出尘子、星宿弟子、摘星子均有
  `set("coagents", ({ ([ "startroom":"/d/xiyu/riyuedong", "id":"ding chunqiu" ]) }))`；
  ex 的 UCL `coagents` 只有 id 列表，缺 `startroom` 条件。
- **#816 神王木鼎状态机**：`azi.c:91-134` 依 `swmuding` 标记、
  `children("/clone/misc/swmuding")` 全局检查、同门判断、
  `combat_exp>500000 && shen<-10000` 给鼎及多分支文案；
  `ding.c:122-136` 在玩家携带鼎时 `kill_ob`。现有 `engage.kill` 仅单分支。
- **共享 #748 随机演示文案**：`masterd.c:214-261` 的 `msg1` 为 `random(4)`、
  结尾 `msg2` 为 `random(5)`；本批只落确定文案，不伪造随机分支。
