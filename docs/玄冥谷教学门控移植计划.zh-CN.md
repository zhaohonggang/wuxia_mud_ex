## 2. 本批实现（Task #817）

### 2.1 teach 数据（4 NPC）

每个 NPC 的 `set_skill` 逐条落为 `teach = { family = "玄冥谷" teach_skills = {...} }`，
`max` 等于该 NPC 自身该技能等级，`gongxian = 0`（与既有批次一致，LPC
`set_skill` 本身不设贡献门槛）：

| NPC | 技能数 | max 区间 |
| --- | --- | --- |
| 百损道人 | 15 | 220（武学修养）～320（内功/掌法） |
| 鹤笔翁 | 14（另 3 条落 `no_teach`） | 200（武学修养）～260 |
| 鹿杖客 | 15（另 2 条落 `no_teach`） | 220（武学修养）～280 |
| 乌旺阿普 | 11 | 20（武学修养）～80 |

`no_teach` 是 **map（硬拒）** 而非平坦列表，对应技能已从 `teach_skills` 剔除：

- 鹤笔翁（`he.c:60-64`）：
  - `xuanming_shengong` →「玄冥神功要我师父百损道人亲自传授。」
  - `xuanming_zhang` →「玄冥神掌要我师父亲自传授，你还是去找他老人家吧！」
  - `dulong_shenzhua` →「这个你还是找我师兄鹿杖客吧，他比我厉害多了！」
- 鹿杖客（`lu.c:60-63`）：前两条同上，无 `dulong_shenzhua`。
- 百损道人 / 乌旺阿普无 `no_teach`（百损道人是掌门，全技能可传；乌旺阿普
  LPC 源码连 `F_MASTER` 都没继承，但 `set_skill` 存在，按既有惯例落 teach，
  收徒侧另落 `deny_all`）。

### 2.5 引擎扩展（向后兼容）

1. **`gate_order = "lpc_xuanming"`**（`Loader.parse_apprentice/1` 白名单新增）：
   负神门之后**先**判 `minggu_xinfa` / `strike`，最后才是经验门，对齐

     分支返回 `min_skills_deny`；`min_exp` 判定排除 `lpc_xuanming`，
     改在技能门之后单独执行。
   - 其余 `gate_order`（`permit_first` / `gender_first` / `lpc_xiaoyao` /
     `lpc_wuyazi`）路径**完全不变**，既有门派零影响。

   `inquiry_grant_lpc/3`）：独立轻功门，位于 `force` 之后、`neili` 之前，
   对应 `masterd.c:195-199` 的 `b["dodge"]`。缺 key 不拦（老配置零影响）。
   蛟龙抱（dodge 150）、如影相随（dodge 180）是首批使用者。

  （鹤笔翁/乌旺阿普的 startroom 是 LPC 未填的占位串，移植时按原样保留不猜测。）
- **#820 masterd.c give_item 持有者遍历**：`masterd.c:474-509` 在给物品前
  沿 `environment()` 上溯找 owner，并分 5 个分支返回不同文案：
  ① owner 就是玩家本人 →「不就是你拿着在用么，怎么反倒找我了？」
  ② owner 非 character →「我已经借出去了，你还是隔段时间再来吧。」
  ③ owner 同门 →「现在是我派的 X 在用，你若需要就去找他吧。」
  ④ owner 与玩家同门（非本派）→「现在是你派的 X 在用，你自己去问他要吧。」
  ⑤ 其他 →「现在落在了 X 手中，你去把它取回来吧。」
  现有 `GiveItem` 仅能表达 family/master/skill/shen/count，缺 owner 遍历与
  这 5 句文案。鹤形笔/鹿头杖的 `note` 已标注 GAP #820。
