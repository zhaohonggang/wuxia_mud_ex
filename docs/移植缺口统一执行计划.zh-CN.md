## 1. 单一事实源与执行纪律

### 1.1 本文件的地位

- 本文件是后续缺口推进的**统一入口**。
- `docs/hell-地藏王-移植计划.zh-CN.md` 的 A–F 大类继续保留，但细节以本文件为准。
- `docs/lpc-port-gaps.zh-CN.md` §15 继续保留“问询闭包 survey”的历史校正过程；本文件引用其**校正后基线**，不重复展开 resolver 调试史。
- TaskList 中的 pending 项作为**候选缺口索引**，不直接等于“真缺口”；每一项先检查后决定保留/关闭/合并。

### 1.2 每一项必须走同一条检查链

1. **读 LPC 原始函数/闭包**：确认真实语义、门序、文案、副作用。
2. **定位 ex 落点**：优先确认 canonical UCL（特别注意 `clone_lib.ucl` 原型与 zone 副本谁实际加载）；再查 handler registry / runtime wiring。
3. **做最小判定**：标记为以下四选一：
   - `REAL_GAP`：LPC 有、ex 无，需实现；
   - `ALREADY_DONE`：代码/数据已实现，TaskList 状态滞后，关单即可；
   - `LPC_DEAD` / `INTENTIONAL_SKIP`：LPC 自身缺陷或已声明有意不回填；
   - `NEEDS_DESIGN`：需要引擎级设计，先写方案，不改代码。
4. **再实现**：只补判定为 `REAL_GAP` 的最小切片，不借机重构。
5. **定向验证**：`validate_ucl.py`（若改 UCL）→ `mix compile`（若改 ex）→ 相关定向测试。
6. **归档**：更新 `docs/待全量回归清单.zh-CN.md`、本文件状态、TaskList 状态、工作区记忆。
7. **全量回归 / commit / push**：只在用户明确授权后执行；commit 时带上 `character_metadata_backup.sql`。
