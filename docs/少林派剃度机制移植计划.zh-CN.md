## 0. 移植策略（先查 ex → 接线 / 移植 → 避免重复）

每个子项一律按以下四步处理，禁止跳过第一步直接重写：

1. **查 ex**：在 `lib/` `data/` `test/` 中定位是否已有等价实现或可复用基础设施。
2. **有则接线**：若已有引擎/命令/事件/数据结构，只做配置或薄封装接线，不改其语义。
3. **无则移植**：确实缺失的，照 LPC 原版实现，逐条对齐检查项与文案。
4. **避免重复**：同款逻辑只保留一处实现；新代码优先复用现有 helper（`Family`、
   `SecularizeCommand` 的 pending 模式、`NpcAskEvent` 的 inquiries 分发等）。

**已完成的 ex 侧核查结论**（详见 §3）：入门引擎、pending 两步确认、inquiries/apprentice
解析均已存在 → 接线为主；剃度仪式、辈分晋升、推荐信斗武、山门守卫、达摩门槛 → 需移植。

## 5. 不简化清单（逐条登记 LPC 原版细节）

> 本节是**验收Checklist**。下列每一条都是容易被"简化实现"吞掉、但必须原样保留的细节。

### 5.1 俗家弟子 `attempt_apprentice` —— 检查顺序不可合并
| NPC | 原版顺序 | 文案 |
|-----|---------|------|
| 清无 qing-wu.c | ①性别≠男性即拒 → ②`permit_recruit` → ③class≠bonze 说俗家弟子 → ④recruit | 「女施主呀，贫僧可不敢开这等玩笑啊」/「贫僧就收下你做『俗家弟子』了」 |
| 清为 qing-wei.c | ①`permit_recruit` → ②性别≠男性即拒 → ③class≠bonze → ④recruit | 同上 |
| 清法 qing-fa.c | ①女性拒 → ②无性拒 → ③class≠bonze → ④recruit | 「这位公公，你还是回去伺候皇上吧」 |

**不简化**：三者顺序与拒答文案不同，必须分别实现，禁止抽成单一"通用收徒"规则。

### 5.2 剃度前置 `ask_for_join()` —— 4 个检查逐条
1. `class == "bonze"` → 「你我同是出家人，何故跟贫僧开这等玩笑？」
2. `gender == "无性"` → 「这位公公，你还是回去伺候皇上吧」
3. `gender == "女性"` → 「女施主若真心皈依我佛，可去后山庵里受戒」
4. 通过 → 设 `pending/join_bonze = 1`，「请跪下(kneel)受戒」

**不简化**：女性/无性两条分别判断、文案独立；不因"都是拒绝"合并。

### 5.3 剃度仪式 `do_kneel()` —— 7 步全做
1. 无 `pending/join_bonze` → `return 0`（静默，不提示）
2. `message_vision`：玩家跪下 + NPC 摩挲头顶剃尽头发（两段文案）
3. 改名：`new_name = prename[random] + name[0..0]`，`prename = {"虚","空","明","净"}`
4. `NAME_D->remove_name(old, id)` → `set("name", new)` → `NAME_D->map_name(new, id)`（姓名注册表更新）
5. `set("class","bonze")`
6. `set("K_record", PKS + MKS)`；`set("shen_record", 原 shen)`；`set("shen", 0)`
7. `delete_temp("pending/join_bonze")`；NPC `say` 法名 + `smile`

**不简化点**：
- `prename` 数组实际只有 4 个元素（源码注释还列了"圆/悟/法"但**未启用**），按实际 4 元素移植。
- `K_record = PKS + MKS`（玩家击杀 + 怪物击杀之和），不是单值。
- `shen_record` 保存剃度**前**的 shen，供山门戒律院分支比较。
- 姓名注册表的 remove/map 两步不可省（否则旧名仍可索引）。

### 5.4 达摩祖师 `attempt_apprentice()` —— 11 项门槛逐条（含顺序）
| # | 检查 | 阈值/条件 | 失败文案 | 是否 return |
|---|------|-----------|----------|------------|
| 1 | `permit_recruit` | 通过 | （见 §5.7） | 失败 return |
| 2 | `family_name` | == "少林派" | 「与本派素无来往，不知此话从何谈起？」 | return |
| 3 | `class` | == "bonze" | 「是俗家弟子，不能在寺内学艺。」 | return |
| 4 | `generation` | == 36（玄字辈） | 「贫僧哪里敢当！」 | return |
| 5 | `query_int()` | >= 35 | 「悟性仍有不足，需要进一步锻炼…」 | **否！只提示不 return（原版行为）** |
| 6 | `WPK` | <= 3 | 「杀戮心太重，不适合继续学习武功。」 | return |
| 7 | `buddhism` | >= 180 | 「禅宗心法领悟得不够…」 | return |
| 8 | `dodge` | >= 180 | 「基本轻功火候尚有欠缺…」 | return |
| 9 | `force` | >= 180 | 「基本内功火候尚有欠缺…」 | return |
| 10 | `parry` | >= 180 | 「基本招架火候尚有欠缺…」 | return |
| 11 | `combat_exp` | >= 1,000,000 | 「实战经验还颇有欠缺…」 | return |
| — | 通过 | 改名 `"渡" + name[1..1]` + `recruit` | — | — |

**不简化点（关键）**：第 5 项 `int < 35` 在 LPC 中**只有 `command("say ...")` 没有 `return`**，
即悟性不足仅口头提示、流程继续，仍可能通过并最终收徒。这是原版行为，**必须保留**，
禁止"顺手修正"为拒绝。移植时须加注释说明这是对 LPC 的忠实复刻。

### 5.5 辈分晋升（推荐信 + 斗武 + 改名）
#### 5.5.1 斗武 `checking()` 判定
- 若 NPC 仍在战斗 → `call_out("checking", 2)` 延迟重查。
- 玩家已离开房间 → 结束。
- **胜利**：`NPC.qi * 100 / NPC.max_qi <= 50`（≤50，含等号）→ 发推荐信 + `have_letter=1`。
- **失败**：`玩家.qi * 100 / 玩家.max_qi < 50`（<50，不含等号）→ 提示多加练习。
- `accept_object` 收 `damo ling`：需 `generation == my_gen + 1` 且 `!have_letter` → 设
  `fight_ok=1`、销毁达摩令；`accept_fight`  Consume `fight_ok` 后启动 `checking`。

**不简化点**：胜负两个不等号不同（胜利 `<=50`、失败 `<50`），必须分别实现。

#### 5.5.2 推荐信四级递进（各字辈不同，禁止简化为单一道具）
| 字辈文件 | 斗武胜利发放 | 晋升所需 | 目标字辈 |
|---------|-------------|---------|---------|
| qing.h | `tuijian xin1` | — | — |
| cheng.h | `tuijian xin4` | 收 `tuijian xin3` + `apprentice_ok` | 慧 |
| hui/dao/xuan 同类 | 各自 xinN | 对应 xin(N-1) | 下一字辈 |
| du.h | 无推荐信 | `valid_in_fumoquan==1` + dodge/force/parry/buddhism>=120 | 玄（金刚伏魔圈路径） |

**不简化点**：du.h 走"金刚伏魔圈"而非推荐信，是独立路径；不得合并进推荐信流程。

#### 5.5.3 各字辈 `attempt_apprentice` 分支
- `generation <= my_gen` → 「贫僧哪里敢当！」拒绝。
- `generation == my_gen + 1` 且（cheng.h 要求 `name[0..0]=="慧"`）→ 「XX的徒弟怎么跑到
  我这儿来了」直接收。
- `generation == my_gen + 2` → 有 `apprentice_ok`（或 du.h 的 `valid_in_fumoquan`）
  才收并改名，否则「你没有推荐信，不能越级拜师」。
- 改名统一 `new_name = 字辈字 + name[1..1]` + NAME_D remove/map。

### 5.6 山门守卫 `valid_leave()` —— 6 分支全做（guangchang1.c）
1. `dir != "north"` → 走原生 `::valid_leave`。
2. 少林派 + `class != "bonze"` → 「俗家弟子不得入寺修行」拒绝。
3. 少林派 + `class==bonze` + `guilty==0` + `K_record==WPK` → 「师兄辛苦了，请进」放行。
4. 少林派 + 上述不满足 → 若 `guilty==0`：`shen_record > shen` 则 `guilty=1` 否则 `guilty=2`；
   重置 `K_record=WPK`、`shen_record=shen`；传送到 `smdian`（戒律院）；返回 -1。
5. 非少林派 + 持 `yingxiong ling`（英雄令）→ 「贵客驾到」放行。
6. 非少林派 + `shen>=0` → 女性「本寺从不接待女客」/ 男性「本寺不接待俗人」拒绝；
   `shen<0` → 「邪魔外道…斩断狗腿」并攻击。

**不简化点**：分支 4 的戒律院判定 + 状态重置 + 传送是完整玩法，禁止省略；英雄令贵客
通道、女客/俗人/邪魔三种区分文案全部保留。

### 5.7 `permit_recruit()` —— 3 条门控（shaolin.h，所有少林 NPC 共用）
1. `detach/少林派` 或 `betrayer/少林派` → 「你反反复复，唉！怎么一心向佛？」拒绝。
2. `betrayer/times` → 「你大逆不道，私自判师，不能容于少林！」拒绝。
3. 已有 `family_name` 且 != "少林派" → 「你已经名师指点，为何…反而来我们少林寺呢？」拒绝。
4. 通过 → 返回 1。
