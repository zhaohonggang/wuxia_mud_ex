## 2. teach 技能（枯荣，LPC `set_skill` 原值）

`family = "大理段家"`，`gongxian = 0`（LPC `recognize_apprentice` 不消耗贡献）。可教仅两项：

- `lamaism = 260`
- `buddhism = 260`

逐字 `no_teach`（其余 NPC 自身会的 10 项都被 `recognize_apprentice` 硬拒）：

- `literate` → `抱歉，想学文化请去找教书先生。`
- `force` / `dodge` / `parry` / `finger` / `tiannan-step` / `kurong-changong` / `duanshi-xinfa` / `sun-finger` / `martial-cognize`
  → `做人不要一味凶猛好杀，尽学一些杀伤人命的武技。`

另：`if (ob->query("shen") < -5000) command("say 你虽魔性太重，但是佛门广大，老衲奉劝施主以后还是多多向善。")` 是**非阻断提示**，不在 `no_teach` 里 → GAP #916。

## 3. 收徒门（apprentice）

四僧 + 枯荣 + 鸠摩智均无 `attempt_apprentice`/自有 `recognize_apprentice`（枯荣的 `recognize_apprentice` 只管 `learn` 授课，不是拜师）。
`F_MASTER` 的 `feature/master.c` 只实现 `prevent_learn` / `attempt_detach`，**未定义 `recognize_apprentice`**；
`feature/apprentice.c` 的 `create_family` / `recruit_apprentice` 只写 family，不提供公开拜师入口。
→ 本批 **不新增 apprentice 块**（与 LPC「无公开拜师入口」一致），不造简化门。

## 4. 枯荣问询（按 born_family 双分支）

`born_family != "段氏皇族"`：
`枯荣大师冷笑一声道：<respect>打听我们天龙寺镇寺之宝干什么？`（respect 引擎统一「大侠」，helper 已建模）

`born_family == "段氏皇族"`：
`枯荣大师淡然对<n>道：你虽然是皇族之人，但是也不得染指六脉神剑剑谱。`

三键共用同一 `ask_me`，但第二分支文案含「六脉神剑剑谱」与键无关，逐字照抄。
引擎新增 `kind = "born_family_reply"`：`required_born_family` 命中走 `msg_match`，否则 `msg_other`；
支持 `$n` 占位符按 `data.asker_name` 替换后房间广播（避免 Task #822 的裸 `$n` 泄漏）。

### 7.1 本批发现并修正的静默陷阱

1. **`max_neili` 伪键不能走 `meets_levels?/2`**：天寰神炎的 `min_levels` 混用真技能与
   `max_neili`，若退回纯技能查表，`max_neili=5000` 会被当成技能 0 而误拒合格玩家。
   已新增 `first_failing_jiumozhi_level/3`，显式 `level_order` 走有序链、缺省也按
   `named_level_value/2` 取命名值；测试锁定三条逐条拒绝文案。
2. **鸠摩智无静态放置**：world loader 只实例化 `room_characters` 引用到的 NPC，
   直接查 `world.characters` 会误判「数据丢失」。LPC 本就只在枯荣战斗中动态创建，
   故测试改走 `Loader.parse_character/4` 解析原始定义，并把动态生成保留为 GAP #915。
3. **`msg_one` 裸 `$n`**：天龙寺两条演示文案含 `$n`，旧广播路径会原样显示
   （GAP #822）。已在 `SectMasterGrant.render_msg1/2` 广播前替换为提问者/NPC 名，
   并用新增用例锁定。
