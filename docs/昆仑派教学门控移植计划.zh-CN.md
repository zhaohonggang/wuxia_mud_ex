- 8/8 无 `apprentice` 块（LPC 全部有 `attempt_apprentice`，并共用 `kunlun.h permit_recruit`）。
- 5/8 完全无 `inquiries`；3/8（班淑娴、何太冲、何足道）仅有 12/12/7 个键，其中绝招键都是

昆仑绝招**不是** `MASTER_D->teach_pfm`，而是各 NPC 的 `ask_skill*()` 内联实现：
`can_perform` 置 1、若干 `improve_skill(..., 1500000)`（实际 +1 级）、`improve_skill("martial-cognize", 1500000)`、
`add("gongxian", -N)`。不得套用绝情谷 `gate_order = "lpc_masterd"`，否则门控顺序与拒绝文案会错位。

## 2. `teach` / `no_teach` 回填（Task #753）

统一 wrapper（loader `parse_teach/1` 只认 character 级 `:teach`）：

```ucl
teach = {
  family = "昆仑派"
  teach_skills = {
    force = { max = 210 gongxian = 0 }
    sanyin_shou = { max = 210 gongxian = 0 }
  }
}
```

- 每 NPC 的 `teach_skills` 取该块现有 `skills` 中全部 `{ skill = ... level = ... }`，
  值即 LPC `set_skill` 的教学上限；`{ type = ... skill = ... }` 是映射，不重复写入。
- 卫四娘、西华子增加：

```ucl
no_teach = {
  liangyi_shengong = "两仪神功需得掌门人亲自传授。"
  zhengliangyi_jian = "正两仪剑法乃本门神功，需要掌门人亲自传授。"
}
```

loader 已把 map 形态落为 `no_teach_deny`，但 `skills_event.teach/2` 尚未消费；见共享缺口 #742，
本批由 #752 一并实现，避免两份拒教文案继续静默丢弃。

## 5. 引擎扩展（Task #752，均显式 opt-in）

1. `gate_order = "lpc_kunlun"`：按昆仑内联顺序判定
   `perform_id` → 已会 → 同门 → 必修技能≥1 → 贡献 → `requires_perform`
   → **`level_order` 指定的有序门槛** → 通过。
2. `level_order = [ "force", "tanqin_jifa", "zhengliangyi_jian" ]` +
   `min_levels` 中的伪技能键 `dex` / `max_neili`：逐条取首个未达标项，按 `level_deny` map
   返回该技能的 LPC 原文。这样 `dex` / `max_neili` 与技能等级的相对顺序可逐招精确复刻。
3. `requires_perform` / `requires_perform_deny`：前置绝招门控，位置如上。
4. `improve_skills = [ ... ]`：`SectMasterGrant` 成功后对每项执行 +1 级提升
   （LPC `improve_skill(skill, 1500000)` + `can_improve_skill` 语义）；
   `martial-cognize` 无条件 +1。缺省为空，老配置零回归。
5. `hard_min_int`：何足道悟性是**硬门**（`return`），与达摩 `min_int` 的「只提示不拒」语义不同；
   二者必须分开，禁止复用 `min_int`。
6. `teachable?/3` 消费 `no_teach_deny`（与 #742 同源），按技能返回 LPC 拒教原文。
7. `betray_sect_deny` / `betray_times_deny` / `other_family_deny`：permit_recruit 三句逐字覆写；
   未配置仍走少林缺省。
