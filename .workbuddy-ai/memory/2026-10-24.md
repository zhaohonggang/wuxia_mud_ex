## R24 线上崩溃修复（23:40 许）：LookEvent 房述覆盖把 nil 写进 description

### 现象（bot 实击）
`docker logs` 里反复出现 `[error] Ranch listener Web.Endpoint.HTTP ... exit with reason:
{:function_clause, [{Kalevala.Output.Tags, :parse_string, [nil, "", "\n", []], ...}]}`，
角色 `grant` 登录后一 look 就掉线。**4 次/数百行**，不是偶发。

### 根因（我自己在 P5-6 批引入）
`lib/kantele/world/room.ex` LookEvent：
```elixir
|> assign(:room, %{context.data | description: Kantele.World.Room.long_description(context.data)})
```
`long_description/1` 在房间**没有** `"long"` 房态时返回 **nil**（绝大多数房间）→
`LookView` `[room.description] ++ features ++ weather_descriptions(room)` 把 nil 混进文本列表 →
`Kalevala.Output.Tags.parse_string(nil, ...)` FunctionClauseError → cowboy websocket 进程退出。
登录流程 `login_controller` 的 `event("room/look", %{})` 也会触发，所以**一上线就崩**。

### 为什么 4653/0 没抓住（关键教训）
- `Room.LookEvent` **零测试覆盖**（`grep -rln LookEvent test/` 空）。
- `room_actions_break_test.exs` 对 `long_description/1` 的单测只断言「无 long 返回 nil」——
  **把坏契约锁死了**，读报告时像"已覆盖"。新原语必须**连调用点一起测**。

### 修法
- 调用点改私有 `with_long_description/1`：仅当返回非空 binary 才 `%{room | description: text}`，否则原样返回。
- 新增 `test/kantele/world/room_look_event_test.exs` **4/0**（`async: false`，`Loader.load()` + `ZoneCache.cache` 播 zone，
  直接构造 `%Context{}` 调 `LookEvent.call/2`）。**把渲染结果真的喂给 `Kalevala.Output.Tags`**（崩溃点本身）。
- **revert 验证**：把修法改回旧写法，测试 **3/4 红**且报出与线上逐字相同的 `parse_string/4` FunctionClauseError —— 证明测试是真防线。
- 同类静态扫描（`lib/` 全量找 `Enum.map` 块内 `if`/`case` 无 else）：仅 `item/effect.ex`、`world/mirror_daemon.ex`
  形态相似，均已有显式 `reject(&is_nil/1)`/`filter`，无第 4 处。

### 验证

### 泛化教训（写进 R24）
1. 「返回 nil 表示无值」的函数，**调用点必须判空**；别写 `%{map | key: f(x)}` 这种把 nil 顺手灌进字段的简洁式。
2. 单测断言了坏契约会让 bug 隐身——**新原语要连调用点一起测**。
3. `Conn.Text.data` 是 list，混入 nil 编译期/渲染期都不报，只在输出处理器才炸，**属于最晚暴露的一类**。
