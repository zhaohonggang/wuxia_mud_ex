
修法：缩短测试名，明细移入注释；并写清 255 字节这条约束，避免后人再踩。
全仓库扫描确认超限仅此 1 处（脚本按 `test/describe "..."` 名 UTF-8 字节数 + 前缀统计）。

## P5-4h 完成（`shaolin:putiyuan`：look_hole / xian / get / close_hole）

### 设计决定

1. **`look_hole` 三档** → 新 handler `RoomStateTiers`（`kind = "room_state_tiers"`）。
   不塞进 `room_temp`（那是「有/无」两分支），因为这里是 **status + book_count 两个键**
   共同决定三段文案。`tiers` 按序取首个 `match` 全命中层，无 `match` 的层是兜底（须放最后），
   `match` 要求房间 state 同名键**精确相等**、缺键不算命中。
2. **`status` / `book_count` 是房间属性**（LPC `set()/query()`，不是 temp）→ UCL 新增
   `state = { status = 0  book_count = 1 }` + `Loader.parse_room_state/1` 播种到 `Room.state`。
   之前文档写「房间 temp」不准确，已在调研文档里更正。
3. **`call_out` 不用 `Room.set_timer/3`**：它投 `{:room_timer,...}` 给 `self()`，房间进程无
   `handle_info` 对应分支（全库零调用方）。改用 `:timer.apply_after(8_000, __MODULE__, :close_hole, [room_id])`，
   回调体只用 `Room.put_state_by_id/3` + `Room.tell_room/2`（任何进程可调，房间没了也安全）。
   已在 `set_timer/3` 的 `@doc` 写清「当前不可用 + 该用什么替代」（R14）。
4. **`do_get` 是首个覆盖全局命令的移植**：4 种目标串之外一律 `:not_handled` 交回 `GetCommand`
   （对应 LPC 三处 `return 0`）。注册表注释里写明了这个契约，改它时必须保住。
5. **发物下移**：`give_item/3`、`give_items/4` 从 `NpcActions.Helpers` 搬到 `RoomActions.Helpers`
   （房间动作也要发物），NPC 侧留薄委托，历史调用点零改动。

### 与 LPC 的唯一差异

LPC 先 `set("book_count", 0)` 再 `load_object(MIJI)`，物品定义缺失时谜题永久失效。
本实现先 `Items.get/1` 校验定义存在，缺失时只报「系统出现故障」且**不动** `book_count`。

## 修掉 Yitian / Kneel 的随机失败（R16：假房间抢 `:global` 名）

### 真因（可复现、可验证）

`:global.register_name/3` 在名字已被占用时**静默返回 `:no`，resolver 根本不会被调用**
（OTP 29 实测：`:yes` / `:no` 两种 resolver 结果都一样，`register_name` 直接 `:no`，
旧持有者保持不动）。两个测试文件的 `register_room/2` 都忽略了这个返回值。

`Room.npc_characters_by_id/1` 只按 `{:global, {Kalevala.World.Room, room_id}}` 找进程，
而夹具把假房间挂到**真实房间 id**（`tulong:was_lou4` / `tulong:jiulou` / `hangzhou:liuhe9`）上。
一旦该名字已被真实房间（或别的进程）占用，夹具注册失败但测试毫不知情 → 读到别人的
`private.characters` → `NpcAttack.kill_ob` 把事件发给真 NPC 进程 → 用例收不到
`combat/start` / `yitian/begin`，最终只表现为 **`assert_receive` 超时 + mailbox 为空**。

### 修法

- `npc_actions_yitian_test.exs`：夹具改**每用例唯一 id**（`setup` 里
  `"ytest:#{System.unique_integer([:positive])}"`，用进程字典传给 `was_lou4/0`、`jiulou/0`）；
  真实 id 改名 `@real_was_lou4` / `@real_jiulou`，只留给「注册表命中」断言。
  `Yitian.run/2` 只用 room_id 读快照、拼频道名，不校验归属 → 零行为影响。
- `npc_actions_kneel_test.exs`：`@room_id` 写死不可换 → 改成「`whereis_name` 取旧持有者 →
  `unregister_name` 摘名 → 注册夹具 → `on_exit` 先摘自己、再把旧名还回去」；
  `FakeRoom` 增加 `{:update, _}` / `{:update_items, _}` 两个 no-op `handle_call`
  （真实加载发现名字被占用时会 update 当前持有者，夹具不是真房间，默认实现会崩）。
- 两处一律 `register_name/2` + 断言 `:yes`：把静默串扰变成一句能看懂的失败。

### 校验

- 单文件：`yitian 23/0` + `kneel 16/0`（合并 39/0），`mix format --check-formatted` 通过。
- 全量 2 次（seed 488742 / 12345）：**3979 tests / 1 failure**，Yitian/Kneel 全绿。
  余下 1 条是另一族（R17：DB sandbox 超时，受害者随机）。

两次全量带 `TRACE_KICKOFF`（`Kickoff.load_world/1` + `start_room/1` 打点）都**没有**

## R17 修完：沙盒「共享属主交接窗口」（全量 0 失败）

### 真因（1 秒必现的最小复现）

三个 Case 模板（`conn_case.ex` / `data_case.ex` / `channel_case.ex`）对 `async: false`
用例执行 `Sandbox.mode(Repo, {:shared, self()})` —— 这是**全局**模式。属主进程退出后，
沙盒管理器要处理完 `DOWN` 才把模式切回 `:manual`。空窗期内，紧随其后的**裸**
`ExUnit.Case` 用例会借到那条**已死**的连接，拿到的是
`DBConnection.Holder.checkout` 抛的 `** (EXIT) shutdown: "owner #PID<...> exited"`
（**exit，不是异常**），`rescue` 抓不到 → 整个用例崩。

复现脚本（已删除）：一个 `use Web.ConnCase, async: false` 模块 + 紧随其后的裸模块里
`Repo.query!` → `{:exit, {{:shutdown, "owner ... exited"}, {DBConnection.Holder, :checkout, ...}}}`；
中间隔一个用例再查则稳定是 `OwnershipError`。

### 为什么这套件里到处是裸用例

套件有 **48 个文件 / 134 处**落库测试从不签出连接，靠 `Records.save/1` 把
`DBConnection.OwnershipError` 当「预期噪音」吞掉过日子（`Logger.debug` 那一支）。
所以不能靠「让每个用例都签出」来修，只能修交接。

### 修法（两层）

1. `conn_case.ex` / `data_case.ex` / `channel_case.ex`：`async: false` 分支加
   `on_exit(fn -> Sandbox.mode(Repo, :manual) end)`，**同步**关掉空窗。
   - 只对同步用例做：异步用例并发跑，`mode(:manual)` 会把别人的连接一起 checkin。
   - `on_exit` 是 LIFO，模板 setup 先注册 → 我们的回调**最后**跑，不会踩到别人的 on_exit 查询。
2. `Records.save/1` 加 `catch :exit, reason -> Logger.error(...) ; :error`。
   连接池取用失败本来就是 exit（`:timeout` / `{:shutdown, "owner exited"}`），
   `rescue` 管不到；不加这一层就违背了它自己 @doc 的「失败只记日志，绝不影响游戏进程」。

### 回归守门人

`test/kantele/db_sandbox_handover_test.exs`（2 条）：A 模块 `use Web.ConnCase, async: false`
签出并进共享模式，B 模块裸 `ExUnit.Case` 紧接着探一次 `Repo.query!`，
断言**不是** `{:exit, ...}`。撤掉 `on_exit` 必红，flunk 文案直接指路到三个 Case 模板。

### 校验

- 单文件：`db_sandbox_handover 2/0`、`sell+backpack+exchange+handover 51/0`；格式通过。
- 全量 **3 次**（seed 488742 / 12345 / 777）：**3981 tests / 0 failures**，每次 ~280s。
  修前是 3979/1（且探针那轮抓到新受害者 `ExchangeTest`，同一签名）。
- `mix credo` 在宿主机跑不了（Elixir 1.20 + 老 ecto，`dynamic/0` 被当内建类型重定义，
  dev 环境编译直接失败）——环境既有问题，与本次改动无关，测试环境正常。

### 仍存的方法论教训

`rescue` 只抓异常，**exit 抓不到**。凡是「失败也不能影响主流程」的边界函数，
要么 `catch :exit`，要么别承诺。这次两条随机失败（R16 的 `:global` 静默 `:no`、
R17 的 exit）都栽在「忽略了一个不抛异常的失败信号」上。
