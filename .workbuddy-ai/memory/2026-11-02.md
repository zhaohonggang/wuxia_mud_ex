## 计划文档核查（对照真实 Ex 源码，用户要求"实现后体验与玩家视角流程一致"）

随后核查 `docs/EX-注册与转世迁移计划.zh-CN.md` 对 Ex 现状的断言，发现并修正：

- **`Stats` 无 `:per`/`:kar`**（`stats.ex:43-61` 结构体、`@derive Jason.Encoder:24-41` 均不含）→ `query_per/3` 只能 `Map.get(stats,:per)||20` 兜底。计划要求补字段+编码，正确。
- **`PlayerMeta.character`/`env` 标注「运行态，不落盘」**（`character.ex:12,20`）—— 即 LPC `set()` 属性（gender/born/surname/registered/age/reborn 计数/三前置 pass 标志）在 Ex 重登会丢。
- **`Metadata` schema 无 `env`/`character`/`per`/`kar` 列**（仅 `gender`，`records.ex:35`），`save/1`（`:152-187`）不写 gender/per/kar/env/character → 既有缺口，计划已纳入。
- **修正失真①**：`spawn_room_id` **仅 `NPCConfig` 有**（`character.ex:399-412`），玩家无此字段 → 计划原「写 spawn_room_id」改「置 `character.room_id` + 持久化于 `meta.env.startroom`」。
- **修正失真②**：`build_character` 对所有登录强制 `room_id = Kantele.World.start_room_id()`（`login_controller.ex:158,163`），玩家当前房**完全不持久化** → 改为：① `meta.env.startroom` 存选定出生地；② `process_character` 回 `startroom`；③ 新玩家问答末步置 `room_id`。
- **补强体验对齐**：新玩家登录即落入 BORN_ROOM 等价点（阎罗殿）做 `washto`/`born` 问答，结束才 teleport 到所选 startroom。

结论：计划已覆盖 DB（character_metadata 加 env/character/per/kar 四列 + migration）、数据类型（Stats 加 per/kar + Jason 编码、PlayerMeta 落盘语义）、控制器（LoginController/SetupController/process_character 出生点改造）、四前置转世链，可实现后体验与玩家视角流程一致。
